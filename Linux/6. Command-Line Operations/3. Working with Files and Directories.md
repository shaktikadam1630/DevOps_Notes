# Working with Files and Directories

This module covers the day-to-day commands for viewing, creating, moving, renaming, and removing files and directories — plus customizing your command prompt.

---

## 1. Viewing Files

![Viewing Files: Which Tool, When](https://github.com/shaktikadam1630/DevOps_Notes/blob/main/Linux/images/file-viewing-tools.png?raw=true)

| Command | Usage |
|---|---|
| `cat` | Views shorter files; no scroll-back |
| `tac` | Views a file backwards, starting from the last line (`tac` = `cat` reversed) |
| `less` | Pages through larger files — pauses per screen, supports scroll-back, search, navigation |
| `tail` | Prints the **last 10 lines** by default |
| `head` | Prints the **first 10 lines** by default |

**Inside `less`:** press `/` to search forward, `?` to search backward.

> **Note:** An older program `more` still exists but has fewer capabilities — hence the saying "less is more."

**Customizing line counts:**
```bash
head -20 file.txt      # first 20 lines
tail -20 file.txt      # last 20 lines (also works as tail -n 20)
```

**Line numbers:**
```bash
cat -n file.txt         # numbered lines with cat
less -N file.txt        # numbered lines with less
```

**Example:** Checking a 5,000-line log file, `cat` would flood your terminal instantly and scroll past before you could read anything — `less` is the right tool here, letting you page through and search for a specific error with `/error`.

## 2. touch

`touch` primarily updates a file's **access and modification timestamps** to the current time. But it has a second common use: **if the file doesn't exist, `touch` creates it empty** — a quick way to make placeholder files.

**Setting a specific timestamp:**
```bash
touch -t 12091600 myfile
```
Format: `[[CC]YY]MMDDhhmm[.ss]` — here, month 12, day 09, hour 16, minute 00 (year defaults to current year).

> **Note:** `ctime` (change time) can't be set directly — it always updates to the *real* current time whenever a file's metadata changes, including when `touch -t` modifies atime/mtime. So after this command, `ctime` reflects *now*, not December 9th.

**Example:** Creating a placeholder file for a script you'll write later: `touch deploy.sh` instantly creates an empty file you can open and edit — no need to open an editor just to save a blank file first.

## 3. Moving, Renaming, and Removing Files

### mv (move / rename)

Same command does both jobs — the destination determines which:

```bash
mv source destination
```

**Rename** (same directory):
```bash
mv notes.txt notes_old.txt
```

**Move** (different directory, name unchanged):
```bash
mv notes.txt /home/student/documents/
```

**Move and rename in one step:** just give a new name at the end of the destination path.

> **Trailing slash matters:** The destination directory must already exist. With a trailing `/` (`documents/`), `mv` errors if it doesn't exist. Without one (`documents`), `mv` instead **renames** `notes.txt` to a file literally called `documents` — rarely what you intended.

### rm (remove)

```bash
rm notes.txt
```

By default, `rm` only removes **files** — running it on a directory fails with "Is a directory." Add `-r` (recursive) to remove a directory and its contents, or `-rf` to also suppress prompts.

| Command | Usage |
|---|---|
| `mv` | Rename or move a file |
| `rm` | Remove a file |
| `rm -f` | Force-remove, no prompts |
| `rm -i` | Interactively remove — asks `y`/`n` before each deletion |

> **Caution:** `rm -f` removes forcefully with **zero warnings**. When unsure about a pattern match, always prefer `rm -i` first.

**Example:** Running `rm -i *.log` prompts you individually for every matching log file — giving you a chance to catch it if the wildcard accidentally matched something you didn't mean to delete, unlike a bare `rm *.log`.

## 4. Creating, Renaming, and Removing Directories

### mkdir

```bash
mkdir sampdir                    # create in current directory
sudo mkdir /usr/sampdir          # needs elevated permission outside your own space
mkdir -p projects/2026/reports   # create parent dirs as needed, all at once
```

Without `-p`, `mkdir` fails if any parent directory in the path is missing.

### Renaming a directory

Same as files — use `mv`:
```bash
mv projects archive
```

### Removing a directory

| Command | Behavior |
|---|---|
| `rmdir sampdir` | Removes only if **empty** (including hidden files) — fails otherwise |
| `rm -r sampdir` | Recursively removes the directory **and everything inside it** |
| `rm -rf sampdir` | Same, but skips all confirmation prompts |

> **Caution:** `rm -rf` deletes permanently, with **no confirmation and no undo**. A wrong argument here can wipe out far more than intended. While learning, prefer `rm -ri sampdir` — prompts before each deletion.

| Command | Usage |
|---|---|
| `mkdir` | Create a directory |
| `mkdir -p` | Create a directory plus any missing parents |
| `mv` | Rename or move a directory |
| `rmdir` | Remove an empty directory |
| `rm -r` | Recursively remove a directory and contents |
| `rm -rf` | Recursively remove, no prompts |

**Example:** `mkdir -p projects/2026/reports` creates all three nested directories in a single command — without `-p`, you'd need three separate `mkdir` calls, one per level, since `mkdir` normally refuses to create a directory whose parent doesn't exist yet.

## 5. Customizing Your Command Prompt

The **`PS1`** variable defines your command-line prompt string.

| Escape Sequence | Shows |
|---|---|
| `\u` | Current username |
| `\h` | Hostname (up to the first `.`) |
| `\w` | Current working directory (`~` for home) |
| `\$` | `#` if root (UID 0), `$` for everyone else |

**Setting it:**
```bash
PS1='\u@\h \$ '
```
Result: `student@r9 $` — note the trailing space, keeping the cursor from sitting right against the `$`.

> **Use single quotes, not double.** Inside double quotes, bash immediately expands `\$` into a plain `$`, permanently losing the dynamic root-vs-user behavior — the prompt would always show `$`, even for root. Single quotes preserve the literal `\$` sequence, so it correctly renders as `$` for regular users and `#` for root.

**Making it permanent:** setting `PS1` this way only affects your current session. Add the line to `~/.bashrc` to make it stick across sessions.

**Example:** An admin who regularly SSHes into multiple servers sets `PS1='\u@\h \$ '` specifically so the prompt always shows exactly which machine and user they're currently working as — a small habit that prevents accidentally running a destructive command on the wrong server.

## Hands-On: Lab 7.3 — Creating, Moving, and Removing Files

**Task:** Create a file, move it using a **relative** path, then delete it using an **absolute** path — to see both styles resolve to the same location.

**Step 1 — Create the file:**
```bash
touch exercise.txt
```

**Step 2 — Move it using a relative path** (from `/home/student`, `..` goes up to `/home`, another `..` reaches `/`, then down into `tmp`):
```bash
mv exercise.txt ../../tmp
```
> `mv` doesn't change your current directory — you're still in `/home/student` afterward.

**Confirm the move:**
```bash
ls /tmp/exercise.txt
```

**Step 3 — Delete it using its absolute path** (works from anywhere, since it always starts at `/`):
```bash
rm /tmp/exercise.txt
```

**Key takeaway:** `../../tmp/exercise.txt` (relative) and `/tmp/exercise.txt` (absolute) pointed to the **exact same file** — the only difference is the starting point. Relative paths are interpreted from your current location; absolute paths always begin at `/`.

## The Full Picture

Day-to-day file management on Linux comes down to a small, consistent toolkit: `cat`/`less`/`head`/`tail`/`tac` for viewing, `touch` for creating empty files or updating timestamps, `mv`/`rm` for moving/renaming/deleting files, and `mkdir`/`rmdir`/`rm -r` for the same operations on directories. The recurring theme across nearly all of them is **caution around irreversibility** — `rm -f` and `rm -rf` delete permanently with no confirmation, which is exactly why `-i` variants exist for anyone still building confidence with these commands. Customizing `PS1` on top of all this is a small but genuinely useful habit, especially once you're working across multiple machines and need an instant, glanceable reminder of exactly where you are.
