# Basic Operations

This module covers the everyday tasks you'll do most often on a Linux graphical desktop: launching applications, setting defaults, and managing files through the file manager.

---

## 1. Launching Applications

Where you find and launch applications depends on your desktop environment, but the concept is identical everywhere: one central, searchable place to access everything installed.

![Launching Applications, Across Desktop Environments](https://github.com/shaktikadam1630/DevOps_Notes/blob/main/Linux/images/launching-applications-comparison.png?raw=true)

**On GNOME** (Ubuntu, Fedora, openSUSE, RHEL): click **Activities** (top-left) or press the **Super key**. This opens the Activities Overview — a search bar plus a grid of open windows. Type an app name and results appear instantly. Click the grid icon at the bottom to browse all installed apps. Ubuntu additionally includes a pinned sidebar dock for quick access, similar to the Windows Taskbar or macOS Dock.

**On KDE Plasma:** click the **Application Launcher** in the taskbar's bottom-left — conceptually the same as the Windows Start menu, with categorized apps and a search bar.

**On Cinnamon** (Linux Mint): click **Menu** in the bottom-left — categorized layout with search, immediately familiar to Windows users.

**Example:** Regardless of environment, the fastest habit is the same: open the launcher, start typing. Searching for "calc" instantly surfaces the calculator app on GNOME, KDE, or Cinnamon alike — no need to remember exactly where it's filed in a menu.

### What Comes Pre-Installed

A standard Linux install typically ships with enough software to handle daily tasks out of the box:

| Category | Common Defaults |
|---|---|
| Web browser | Firefox (Ubuntu, Fedora default); Chromium available in repos |
| Office suite | LibreOffice — compatible with Word, Excel, PowerPoint |
| Email | Thunderbird |
| Media | Rhythmbox (audio), Totem (video) on GNOME |
| File manager | Nautilus (GNOME), Dolphin (KDE), Nemo (Cinnamon) |

Beyond these, software repositories hold thousands of additional apps installable in a few clicks via the software center or package manager.

## 2. Locating Applications

Applications are organized into functional categories in the launcher — Office, Internet, Sound & Video, Utilities, etc. — consistent across GNOME, KDE, and Cinnamon, though category names vary slightly.

If browsing doesn't turn it up, **search**: open the launcher and type a name or keyword. Search typically covers app names, descriptions, and sometimes even file contents.

**Example:** Looking for a screenshot tool but unsure of its exact name? Typing "screen" in the launcher search on GNOME surfaces "Screenshot" immediately, without needing to browse through the Utilities category manually.

---

## 3. Setting Default Applications

When multiple apps can handle the same file type (two browsers, two media players), Linux lets you choose which one opens by default.

**On GNOME-based distributions:**
1. Open **Settings**
2. Go to **Default Applications** (Fedora) or **Apps → Default Apps** (Ubuntu)
3. Assign your preferred app for each category — web browser, email, calendar, music, video

The list only shows what's actually installed on your system, so it varies machine to machine.

| Desktop Environment | Where to Find It |
|---|---|
| GNOME | Settings → Default Applications / Apps → Default Apps |
| KDE Plasma | System Settings → Applications → Default Applications |
| Cinnamon | System Settings → Preferred Applications |

**Example:** After installing VLC alongside the default Totem video player, opening Settings → Default Apps and switching Video to VLC means every video file you double-click from then on opens in VLC instead — no more picking manually each time.

**Practical tip:** Set your defaults *before* you need them. Once you install a second browser, the system needs to know which one opens when you click a link in an email — sorting this out early avoids the confusion of apps opening somewhere unexpected.

## 4. Managing Files with the File Manager

Every major Linux desktop includes a graphical file manager — the equivalent of File Explorer (Windows) or Finder (macOS).

| Desktop Environment | File Manager |
|---|---|
| GNOME | **Files** (Nautilus) |
| KDE Plasma | **Dolphin** |
| Cinnamon | **Nemo** |

**Opening it:** click its icon in the dock/sidebar, search "Files" in your launcher, or run `nautilus` from the terminal (GNOME systems). It opens by default to your **Home directory**.

### Understanding the Home Directory

Every user account has a dedicated home directory at `/home/username` (e.g., `/home/student`) — your personal space, inaccessible to other standard users without permission.

![Your Home Directory](https://github.com/shaktikadam1630/DevOps_Notes/blob/main/Linux/images/home-directory-structure.png?raw=true)

When an account is created, standard subdirectories are auto-generated:

| Folder | Purpose |
|---|---|
| `Documents` | Personal files and documents |
| `Downloads` | Default destination for internet downloads |
| `Desktop` | Files here appear on the visual desktop |
| `Pictures` / `Music` / `Videos` | Organized media folders |

**Example:** Downloading a PDF from your browser lands automatically in `~/Downloads` — exactly the same convention as Windows and macOS, so nothing here feels unfamiliar.

> **Never delete your Home directory.** It holds not just your personal files but also every hidden configuration file for your desktop and applications. Deleting it can prevent you from logging in and wipes all your settings permanently.

## 5. Viewing Files and Directories

The file manager offers two view modes, toggled anytime:

| View | Best For | Shortcut |
|---|---|---|
| **Icons** | Browsing images and media visually | `Ctrl+1` |
| **List** | Large numbers of files — shows name, size, type, date | `Ctrl+2` |

**Sorting:** In Nautilus, use View → Sort By to order files by name, size, type, or modification date — equivalent to right-click → "Sort by" in Windows Explorer.

**Hidden files:** files/folders starting with a dot (`.`) are hidden by default since they usually hold configuration data. Toggle visibility with **Ctrl+H** or View → Show Hidden Files.

**Example:** Pressing Ctrl+H in your home directory suddenly reveals `.bashrc`, `.config`, `.mozilla`, and dozens of other dotfiles — all quietly storing settings for your shell and applications that you never see during normal browsing.

**Zoom:** View → Zoom In/Out adjusts icon size — handy in image-heavy folders.

## 6. Searching for Files

Nautilus includes a built-in recursive search:

1. Click the magnifying glass icon, or press **Ctrl+F**
2. Type a keyword — the file manager searches from the current directory downward
3. Press Ctrl+F again to exit search mode

**Jumping to a known path:** press **Ctrl+L** to open a location bar and type the path directly — the Linux equivalent of typing a path into Windows Explorer's address bar.

### Refining a Search

Once an initial search runs, you can filter further:

- **Filter by Location** — narrow to a specific directory
- **Filter by File Type** — limit to documents, images, PDFs, etc.
- Click **+** to combine multiple criteria at once

**Example:** To find a PDF containing "Linux" in your home folder: navigate home, search "Linux," click **+**, choose File Type → PDF. Results narrow down instantly.

## 7. Editing and Deleting Files

### Quick Text Editing

Double-click any text file to open it in its default editor. On GNOME, that's **gedit** (branded "Text Editor" in recent versions) — clean, with syntax highlighting, spell check, and line numbering. Good for config files, quick notes, or scripts.

### Deleting Files and Using the Trash

Deleted items move to the **Trash** first, not disappearing immediately — giving you a chance to recover them.

![Deleting Files: The Trash Safety Net](https://github.com/shaktikadam1630/DevOps_Notes/blob/main/Linux/images/delete-trash-workflow.png?raw=true)

**To delete:**
1. Select the item(s) — hold **Ctrl** to multi-select, **Shift** to select a range
2. Right-click → **Move to Trash**, or press **Ctrl+Delete**

Deleted items land at `~/.local/share/Trash/files/`. Click **Trash** in the left panel to browse and restore them.

**Permanently deleting:**
- Right-click **Trash** → **Empty Trash** (removes everything, irreversible)
- Or select a file and press **Shift+Delete** to bypass Trash entirely and delete immediately — use with real caution, since this cannot be undone

**Example:** Accidentally deleted an important file? As long as you only used "Move to Trash" (not Shift+Delete), it's sitting safely in `~/.local/share/Trash/files/`, one right-click-restore away from being back exactly where it was.

## Hands-On: Lab Recaps

### Lab 4.2 — Finding the Most Recently Modified File in `/var/log`

1. Open **Files**, press **Ctrl+L**, type `/var/log`, press Enter (fastest method — works on all GNOME systems)
2. Switch to **List view** (`Ctrl+2`)
3. Click the **Modified** column header to sort by date; click again to reverse the order
4. The most recently modified file now sits at the top

`/var/log` holds system log files — records of OS and application activity, covered in more depth later in this series.

### Lab 4.3 — Creating, Deleting, and Recovering a File

**Create `lab.txt`:**
```bash
touch ~/lab.txt
```
(Or right-click → New Document in the file manager, if your Templates folder has a template file — enable this first with `touch ~/Templates/Empty\ Document`.)

**Delete it:** select `lab.txt` → right-click → **Move to Trash** (or `Ctrl+Delete`)

**Verify it's in Trash:** press `Ctrl+H` to show hidden folders, navigate to `.local → share → Trash → files`, and confirm `lab.txt` is there — or just click **Trash** in the sidebar.

**Restore it:** open Trash, right-click `lab.txt` → **Restore**. It returns to your home directory.

## The Full Picture

Every graphical Linux task in daily use follows the same underlying pattern: a searchable **launcher** finds any app in seconds, **Default Applications** settings decide what opens what, and the **file manager** — Nautilus, Dolphin, or Nemo depending on your desktop — handles everything from browsing your **Home directory** to searching, sorting, and safely deleting files through the **Trash**. None of this requires the command line, but understanding exactly what's happening underneath (real file paths, real hidden config files, a real Trash directory) makes the transition to the terminal — covered next — feel like less of a leap.
