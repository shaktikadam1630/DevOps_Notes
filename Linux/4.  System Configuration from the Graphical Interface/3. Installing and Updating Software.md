# Installing and Updating Software

This module covers how software actually gets installed and managed on Linux — through **packages**, the two layers of tooling behind them, and the graphical package managers you'll use across every major distribution family.

---

## 1. Understanding Package Management

Software on Linux is distributed in **packages** — self-contained bundles that include program files, configuration files, documentation, and metadata. Every component of a Linux system, from the kernel itself to your web browser, is delivered and managed as a package.

### Dependency Management

Most packages rely on other packages to function — a defining characteristic of Linux packaging. An email client supporting encrypted connections, for example, **depends on** a package providing SSL/TLS libraries. The package manager understands these relationships and installs required dependencies automatically.

**Example:** Installing a photo editor might silently pull in three or four supporting libraries you never explicitly asked for — the package manager knows the editor needs them and handles it without you having to hunt each one down manually.

### Two Layers of Tooling

Every distribution has:

- **A low-level package manager** — unpacks files and places them in the correct locations, but does **not** resolve dependencies automatically
- **A high-level package manager** — talks to online repositories, downloads packages *and* their dependencies automatically, and provides the interface (graphical or CLI) most software management happens through

High-level tools work by downloading **metadata** from repositories — essentially a local "catalog" of available software and version numbers. This is why the local catalog needs periodic refreshing (an update command) before the system can "see" the latest available software or security patches.

For day-to-day use, you'll almost always interact with the **high-level** tools. The two dominant systems: **APT/dpkg** (Debian-based) and **RPM** (Red Hat/SUSE-based).

## 2. Debian Packaging: APT and dpkg

Debian-based distributions (Ubuntu, Linux Mint) use **dpkg** as the low-level tool — it can install, remove, and inspect individual `.deb` files directly, but doesn't connect to repositories or resolve dependencies on its own.

The high-level tool is **APT (Advanced Package Tool)**, which builds on dpkg and adds repository connectivity, automatic dependency resolution, and system-wide update management. APT is what runs behind the `apt` and `apt-get` commands.

> Each distribution maintains its own repositories. The APT format is standardized, but packages are built specifically for each distribution and version — installing packages from a repository targeting a different distribution can cause conflicts, and isn't recommended.

### Graphical Tools on Debian-Family Systems

| Tool | What It Is |
|---|---|
| **App Center** (Ubuntu 23.10+) / **GNOME Software** (older versions) | Modern, app-store-style interface for browsing, installing, removing software |
| **Synaptic Package Manager** | Older but more detailed — better for advanced package tasks, available in repos if not preinstalled |
| **Snap** | A distribution-neutral format from Canonical — self-contained, bundles its own dependencies, updates automatically. Coexists alongside APT packages on the same system |

**Example:** Searching "Cheese" (a webcam app) in Ubuntu's App Center often shows **two** results — a Snap version and a regular Debian (`.deb`) package. Both do the same thing, but the Snap includes all its own dependencies bundled in, while the `.deb` version relies on shared system libraries via APT.

## 3. Red Hat Package Manager: RPM and DNF

RPM-based distributions (Fedora, RHEL, CentOS Stream, openSUSE) use **RPM** as the low-level package format and tool.

The current high-level manager on Fedora and RHEL is **DNF**, which replaced the older `yum` tool — handling repository management, dependency resolution, and system updates from the command line.

**Graphical tool:** Fedora and RHEL use **GNOME Software** — functionally identical to its Ubuntu counterpart, same browsing/install/update experience.

---

## 4. openSUSE: YaST Software Management

openSUSE uses RPM as its package format and **Zypper** as its command-line package manager. For graphical management, it offers **YaST Software Management** — widely considered one of the most feature-rich graphical package managers on any Linux distribution.

**Opening YaST Software Management:**
1. Open the Activities Overview, type "YaST," select the YaST icon
2. Enter your administrator password when prompted
3. Select **Software Management**

From here, search by name/keyword, browse by category, and **mark** packages for install or removal. YaST **queues** all marked changes and processes them together when you click **Accept** — automatically resolving dependencies before proceeding. This batch approach is efficient when managing several packages at once.

**Example:** Marking five different packages for installation and one for removal, then clicking Accept once, is faster and less error-prone than installing/removing each one individually — YaST works out the full dependency picture across all six changes together.

> **Note:** YaST covers far more than software — network configuration, user management, and system services all live in the same tool.

## 5. Installing and Updating Software: Walkthrough (Ubuntu)

Most experienced administrators use the command line for package management, but every major distribution also ships one or more graphical tools. Here's how the main Ubuntu options compare in practice:

### GNOME Software

- Opens to an **Explore** tab with categories: Create, Socialize, Work, Learn, Play, Develop
- **Installed** tab lists everything currently installed, alphabetically
- **Updates** tab shows pending updates (individually or via "Update All")
- Search via the magnifying glass icon — results may show both a **Snap** and a regular package for the same app
- Installing requires **authentication** (your password), since software installation needs elevated privileges
- Once installed, the Install button becomes an **Uninstall** button

### App Center (Ubuntu-specific)

Very similar to GNOME Software in layout and function — categories, search, install/uninstall — but breaks results into **Snap** vs. **Debian package** sections explicitly when both exist.

### Synaptic Package Manager

A more detailed, "micro-management" tool:
- Requires authentication
- Categorized sidebar for browsing
- Search checks both package **name** and **description**
- Right-click a package → **Mark for Installation**
- View **Properties** — version, download size, and full **dependency list**
- Nothing installs until you explicitly apply the marked changes

**Example:** Someone new to Linux is generally better served by GNOME Software or the App Center — simple, app-store-like, hard to break anything. Synaptic is the better tool once you want to see exactly which dependencies a package pulls in before committing to the install.

**The takeaway:** All of these tools are fundamentally similar and available across nearly every GNOME-based distribution — if GNOME Software isn't preinstalled, it can be added as a package (via the command line).

## Hands-On: Lab — Installing and Removing Software Packages

**Objective:** Use your distribution's graphical package manager to locate the `dump` package (a backup utility for ext2/ext3/ext4 filesystems), install it, then remove and reinstall it — observing how dependencies are handled.

### Step 1: Open the Package Manager

| Distribution | Tool |
|---|---|
| **Ubuntu** | App Center (sidebar dock or Activities search); older versions use GNOME Software; Synaptic gives a more detailed view if installed |
| **Fedora / RHEL / CentOS Stream** | GNOME Software (Activities Overview), or Applications → System Tools → Software |
| **openSUSE** | YaST Software Management (search "YaST" → Software Management → enter admin password) |

### Step 2: Search for the Package

In whichever tool you're using, locate the search bar and type `dump`. Results show every package whose name or description contains that keyword — identify the one named exactly **`dump`** and select it to view details.

### Step 3: Install the Package

If `dump` isn't currently installed, select it and click **Install**. You'll be prompted for your administrator password, since installing requires elevated privileges. The package manager identifies and installs any required dependencies alongside it. Wait for installation to complete.

### Step 4: Remove and Reinstall

If `dump` is already installed (or once you've just installed it), locate it again and select **Remove**/**Uninstall**. Confirm when prompted and wait for it to finish. Then search for it again and reinstall it using the same steps.

**Example:** Watching the dependency list during this lab — even a small utility like `dump` may pull in a couple of supporting libraries the first time it's installed, but removing and reinstalling shows the package manager recognizing what's already satisfied on the system versus what needs to be fetched again.

> **Note:** Exact interface appearance varies between distributions and versions, and changes with each release. If you can't immediately find a specific button, explore the menus — graphical package managers are designed to be intuitive, and the core workflow (search, install, remove) is consistent across all of them. Navigating an unfamiliar interface and finding what you need is itself a useful skill.

## The Full Picture

Every piece of software on a Linux system arrives as a **package** — and every distribution splits package handling into two layers: a **low-level tool** (`dpkg`, `RPM`) that unpacks files, and a **high-level tool** (`APT`, `DNF`, `Zypper`) that talks to repositories and resolves dependencies automatically. Day to day, you'll interact with this through a graphical layer on top — **GNOME Software**, the **App Center**, **Synaptic**, or **YaST** — all built around the same basic workflow: search, install, remove. Learn this pattern on one distribution, and it transfers almost entirely to any other.
